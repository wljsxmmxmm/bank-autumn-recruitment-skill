# 银行简历竞争力评估

用户上传简历、粘贴简历文本、选择按模板介绍自己，或要求判断“能不能投银行/适合哪类银行/短板在哪里”时读取本文件。

## 输入方式

用户有两种方式进入评估:

1. `上传/粘贴简历`: 先解析教育、目标、实习、项目、证书、校园经历和求职偏好，再进入评分。
2. `按模板自述`: 当用户没有简历、暂时不想上传简历，或简历解析信息不足时，给用户这个模板。

```markdown
请按你方便的程度补充，不确定可以写“暂不清楚”:

1. 教育背景: 本科/硕士学校层次、专业、毕业届别、成绩/排名/奖学金
2. 目标: 城市、银行类型、岗位方向、是否排斥柜面/营销/异地
3. 实习: 银行/券商/基金/会计师事务所/其他实习，写清岗位、工作内容、结果
4. 项目: 课程、科研、竞赛、数据分析、风控、行业研究、商业分析等
5. 证书: 基金/证券/银行从业、CPA/CFA/FRM/英语等
6. 校园经历: 学生干部、社团、志愿、竞赛、组织活动等
7. 约束: 签约、家庭城市、薪资底线、不能接受的岗位属性
```

如果简历解析或模板内容不完整，不要硬评完整结论。先追问 1-3 个最影响判断的问题，优先补:

- `目标岗位/城市`: 决定权重和银行池。
- `实习细节和结果`: 决定业务岗、金融市场、管培能否站住。
- `成绩/证书/项目/校园经历`: 决定政策行、总行和高竞争岗位是否值得冲刺。

## 评估前提

- 先从用户材料中提取可确认经历；没有看到就写 `未见相关经历`，不要替用户脑补。
- 评分是校招准备优先级，不是录用预测。
- 每个维度必须同时输出 `得分`、`相关经历`、`判定理由`、`提升建议`。
- 输出区块使用 `用户背景`，不要写 `用户事实`。
- 对未补齐的信息写 `待用户确认`；不要写 `待核验` 或 `待验证` 作为用户可见状态。
- 语言要真实，允许犀利指出短板；不要把普通经历包装成强竞争力。
- 目标岗位或银行类型不明确时，先用 `银行通用校招` 评分，再提示用户可按政策行、国有行、股份行、城商农商行复评。

## 六维评分模型

| 维度 | 默认权重 | 看什么 | 常见高分经历 |
|---|---:|---|---|
| 学历背景 | 25% | 学校层次、学历层次、毕业届别、成绩、奖学金 | 双一流/财经强校/硕士、成绩排名、奖学金 |
| 金融/银行相关实习 | 25% | 银行、券商、基金、会计师事务所、金融科技、总分行业务或中后台 | 银行总分行实习、风控/投研/运营/科技项目、量化结果 |
| 专业对口度 | 15% | 金融、经济、会计、统计、数学、计算机、法学等与目标岗的关系 | 金融经济会计对业务岗，理工/计算机对金融科技和数据岗 |
| 证书 | 15% | 与银行岗位相关的资格和考试进度 | CPA/CFA/FRM 优先；中级会计次之；银从/基从/证券从业为基础加分 |
| 项目经历 | 10% | 金融竞赛、科研、数据分析、风控建模、商业分析、课程项目 | 有角色、方法、结果、排名、数据或可追问细节 |
| 校园经历 | 10% | 学生会、社团、志愿、竞赛组织、班委、宣讲活动 | 体现组织、沟通、执行、责任心和稳定性 |

## 银行类型微调

只在用户指定目标银行类型时微调；不要把全部权重同时改乱。

| 目标银行 | 微调 |
|---|---|
| 政策性银行 | 学历背景上调 5-10 个百分点；党员、学生干部、公共政策/宏观研究经历单独写入理由；实习权重可小幅下调 |
| 国有六大行 | 学历、专业、稳定性、城市匹配均衡；分行岗要重看地域稳定性和服务意识 |
| 股份制银行 | 实习和业务结果上调 5-10 个百分点；更重视抗压、业务理解、数据化表达和效率 |
| 城商行/农商行 | 地域匹配、稳定性、服务意识和本地资源更重要；学历不应机械压倒城市适配 |

## Gotchas

- 不要用“学校一般所以没机会”这种单因子结论；银行校招是梯队和岗位组合问题。
- 不要把 CPA/CFA/FRM 写成必须项；它们是加分经历，不是多数岗位的绝对门槛。
- 不要把 `上岸概率` 写成精确百分比；只能给区间，并说明它来自材料匹配度和岗位竞争强度推断。
- 不要只给总分；总分必须能回到用户材料和相关经历。
