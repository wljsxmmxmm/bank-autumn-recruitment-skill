# 邮件提醒规范

当用户要求“邮件提醒”“发现新岗位发邮件”“截止日期快到前发邮件”时，使用本规范。在线投递工作台是主记录；邮件只是提醒通道，发送结果必须回写工作台。

## 触发条件

只在这些情况下发送邮件：

- 新增可投岗位: 当日巡检发现与用户目标匹配、未重复、来源链接可访问，且状态为待核验/未投的岗位。
- 截止临近: 已在在线工作台中的岗位，截止日期距离当前日期 3 天内，且状态为待核验/未投。
- 今日处理: 用户明确要求邮件提醒今日处理项时，提醒级别为今日处理的岗位也可合并发送。

不发送邮件：

- 状态为已投、测评/笔试、面试、体检、offer、拒绝、放弃，除非用户明确要求流程提醒。
- 截止日期、来源链接和官方标题都无法核验的二手线索。
- 同一岗位、同一提醒原因在同一天已经发送过。

## 必要信息

发送前必须确认：

- 收件邮箱: 用户提供或从可用账户中明确取得。
- 邮件发送工具: 当前环境存在可调用的邮箱发送能力。
- 岗位来源: 至少有来源链接；官方链接优先。

如果缺少收件邮箱或邮件发送工具，不要声称邮件已发送。应回写在线工作台:

- `邮件提醒状态=发送失败`
- `邮件提醒原因=发送失败`
- `复盘记录` 说明缺少邮箱地址或邮箱发送工具

## 工作台字段

投递工作台必须包含这些邮件字段：

| 字段 | 类型建议 | 用途 |
|---|---|---|
| 邮件提醒状态 | Select | 待发送/已发送/无需发送/发送失败 |
| 邮件提醒原因 | Multi-select 或 Select | 新增可投/截止临近/今日处理/发送失败 |
| 上次邮件时间 | Date | 防重复发送和追踪 |

可选字段：

| 字段 | 类型建议 | 用途 |
|---|---|---|
| 收件邮箱 | Email | 用户希望逐行指定邮箱时使用；默认不逐行填写 |

## 发送节奏

- 每日巡检后立即发送新岗位邮件。
- 截止临近邮件默认在每日 09:00 巡检后发送。
- 同一天有多条提醒时，优先合并为一封摘要邮件，避免刷屏。
- P0 紧急提醒包括: 截止日期当天、截止日期明天、状态为未投且提醒级别为今日处理。

## 邮件主题模板

新增岗位:

```text
[银行秋招] 今日新增可投岗位 {新增数量} 个
```

截止临近:

```text
[银行秋招提醒] {公司名称} {岗位名称} 截止日期临近
```

合并摘要:

```text
[银行秋招日报] 新增岗位 {新增数量} 个，临近截止 {截止数量} 个
```

```markdown
|---|---|---|---|---|---|
| ... | ... | ... | ... | ... | ... |

临近截止:
| 公司 | 岗位 | 截止日期 | 状态 | 今日动作 |
|---|---|---|---|---|

- 已投岗位不要重复投递，改为记录反馈和准备笔面试。

```

## 发送后回写

邮件发送成功后，逐条更新在线工作台：

- `邮件提醒状态=已发送`
- `上次邮件时间=真实发送时间`
- `复盘记录` 追加邮件发送摘要，例如 `已邮件提醒: 新增可投` 或 `已邮件提醒: 截止临近`

邮件发送失败后，逐条更新在线工作台：

- `邮件提醒状态=发送失败`
- `复盘记录` 追加失败原因

## 边界

- 不把邮件发送成功等同于岗位真实有效；岗位事实仍以官方页面为准。
- 不发送包含敏感个人信息的邮件，除非用户明确要求。
- 不在没有邮箱工具、没有收件邮箱或发送失败时说“已发送”。
