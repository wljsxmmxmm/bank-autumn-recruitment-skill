# 邮件提醒规范

当用户要求“邮件提醒”“截止日期快到前发邮件”时，使用本规范。在线投递工作台是主记录；邮件只是提醒通道，发送结果必须回写工作台。

## 触发条件

只在这种情况下发送邮件：

- 截止临近: 已在在线工作台中的岗位，截止日期距离当前日期 3 天内，且状态为待用户确认/未投。

不发送邮件：

- 状态为已投、测评/笔试、面试、体检、offer、拒绝、放弃，除非用户明确要求流程提醒。
- 截止日期缺失的岗位。
- 同一岗位、同一提醒原因在同一天已经发送过。

## 必要信息

发送前必须确认：

- 收件邮箱: 用户提供或从可用账户中明确取得。
- 邮件发送工具: 当前环境存在可调用的邮箱发送能力。
- 岗位来源: 优先使用官方链接；若官方链接缺失，可用 Notion 页面链接兜底提醒用户回表处理。

如果缺少收件邮箱或邮件发送工具，不要声称邮件已发送。应回写在线工作台:

- `邮件提醒状态=发送失败`
- `邮件提醒原因=发送失败`
- `复盘记录` 说明缺少邮箱地址或邮箱发送工具

## 工作台字段

投递工作台必须包含这些邮件字段：

| 字段 | 类型建议 | 用途 |
|---|---|---|
| 邮件提醒状态 | Select | 待发送/已发送/无需发送/发送失败 |
| 邮件提醒原因 | Select | 截止临近/发送失败 |
| 上次邮件时间 | Date | 防重复发送和追踪 |

可选字段：

| 字段 | 类型建议 | 用途 |
|---|---|---|
| 收件邮箱 | Email | 用户希望逐行指定邮箱时使用；默认不逐行填写 |

## 发送节奏

- 截止临近邮件默认在每日 09:00 巡检后发送。
- 同一天有多条提醒时，优先合并为一封摘要邮件，避免刷屏。
- P0 紧急提醒包括: 截止日期当天、截止日期明天、状态为未投的 P0/P1 岗位。

## 本地草稿生成

在真正调用邮箱工具前，先生成邮件草稿和回写建议，不做真实发送:

```bash
python3 scripts/generate_email_reminders.py --input rows.json --today 2026-06-15 --recipient user@example.com --output email-draft.md
```

脚本输出:

- `To` 和 `Subject`。
- 合并后的临近截止清单。
- `dry-run: 未发送` 状态。
- `回写建议`: 每条记录应写回的 `邮件提醒状态`、`邮件提醒原因`、`上次邮件时间`。

只有用户确认草稿、收件邮箱明确、且 Gmail/邮箱工具可用时，才进入真实发送。真实发送成功后再按回写建议更新在线工作台；发送失败时回写失败原因。

## 邮件主题模板

截止临近:

```text
[银行秋招提醒] {公司名称} {岗位名称} 截止日期临近
```

合并摘要:

```text
[银行秋招提醒] 临近截止 {截止数量} 个
```

## 邮件正文模板

```markdown
你好，以下银行秋招机会临近截止，请尽快处理。

临近截止:
| 公司 | 岗位 | 截止日期 | 状态 | 今日动作 | 来源 |
|---|---|---|---|---|---|
| ... | ... | ... | 待用户确认/未投 | ... | ... |

建议:
- 优先处理 P0 岗位。
- 截止日期或岗位说明未核验的岗位，先打开官方链接确认。
- 已投岗位不要重复投递，改为记录反馈和准备笔面试。
```

## 发送后回写

邮件发送成功后，逐条更新在线工作台：

- `邮件提醒状态=已发送`
- `上次邮件时间=真实发送时间`
- `复盘记录` 追加邮件发送摘要，例如 `已邮件提醒: 截止临近`

邮件发送失败后，逐条更新在线工作台：

- `邮件提醒状态=发送失败`
- `复盘记录` 追加失败原因

## 边界

- 不把邮件发送成功等同于岗位真实有效；岗位事实仍以官方页面为准。
- 不发送包含敏感个人信息的邮件，除非用户明确要求。
- 不在没有邮箱工具、没有收件邮箱或发送失败时说“已发送”。
