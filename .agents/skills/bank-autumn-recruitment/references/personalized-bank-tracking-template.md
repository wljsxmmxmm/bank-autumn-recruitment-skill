# 个性化银行秋招投递表模板

当用户希望投递表“像秋招企业信息汇总及面试进度表”一样可执行时读取本文件。原则是: 银行库负责事实，咨询 Skill 负责判断，投递表负责执行。

## 样表观察

用户样表包含四类工作区:

- `秋招信息及面试进度`: 主投递表，字段克制，覆盖公司、投递日期、起止时间、类别、批次、岗位、链接、备注、简历、笔试、一面、二面、三面。
- `笔面试`: 日程表，按日期、时间、公司、事项记录。
- `TIP`: 咨询过程中的策略提醒和复盘经验。
- `JD`: 岗位原文或长文本沉淀区。

银行版不要把所有信息塞进主表。主表要像操作台，长公告和 JD 放到旁表或外部链接。

## 生成链路

1. 从 `bank-recruitment-library-*` 读取银行事实: 银行名称、银行类型、同类型梯队、官方招聘网站、网申入口、最近一年公告。
2. 从用户简历和偏好生成咨询判断: 推荐岗位方向、优先级、推荐理由、主要风险、简历版本。
3. 生成 Markdown 投递表预览；用户确认后再转外部在线文档。
4. 外部在线文档按 `external-doc-conversion-rules.md` 设置字段类型、视图、提醒和状态枚举。

## 主表字段

这是银行版的默认主表，接近用户样表，但加入少量银行定制字段。

| 字段 | 来源 | 类型 | 说明 |
|---|---|---|---|
| 银行名称 | 银行库 | 文本/标题 | 例如中国建设银行 |
| 银行类型 | 银行库 | 单选 | 政策性银行/国有六大行/股份制银行/城商行/农商行 |
| 同类梯队 | 银行库 | 单选 | 政策性-T1、国有大行-T1、股份行-T1、城商行-T1 等 |
| 投递优先级 | 咨询判断 | 单选 | P0主攻/P1重点/P2冲刺/P3观察/放弃 |
| 推荐岗位方向 | 咨询判断 | 多选/文本 | 管培、金融科技、数据分析、风控、运营、客户经理、柜面等 |
| 投递批次 | 银行库/实时核验 | 单选 | 秋招提前批/秋招正式批/补录/春招/暑期实习 |
| 开始时间 | 银行库/实时核验 | 日期 | 网申开始日；未知留空或待验证 |
| 截止时间 | 银行库/实时核验 | 日期 | 用真实日期；未知留空或待验证 |
| 投递日期 | 用户执行 | 日期 | 用户实际投递日期 |
| 官方招聘网站 | 银行库 | URL | 官方招聘页 |
| 网申入口 | 银行库 | URL | 投递入口 |
| 公告链接 | 银行库/实时核验 | URL | 最近一年公告或专题页 |
| 简历版本 | 咨询判断 | 单选 | 银行业务版/金融科技版/风控版/城市分行版/政策行冲刺版 |
| 投递状态 | 用户执行 | 单选 | 待核验/未投/已投/测评/笔试/一面/二面/三面/体检/offer/拒绝/放弃 |
| 笔试 | 用户执行 | 日期/文本 | 有明确时间用日期；否则写待通知/已完成/放弃 |
| 一面 | 用户执行 | 日期/文本 | 有明确时间用日期；否则写待通知 |
| 二面 | 用户执行 | 日期/文本 | 同上 |
| 三面/终面 | 用户执行 | 日期/文本 | 同上 |
| 推荐理由 | 咨询判断 | 长文本 | 为什么建议投 |
| 主要风险 | 咨询判断 | 长文本 | 学历、专业、实习、城市、岗位性质、笔试等风险 |
| 下一动作 | 执行生成 | 文本 | 核验公告/准备简历/投递/准备笔试/面后复盘 |
| 提醒日期 | 执行生成 | 日期 | 截止前 3 天、笔试前 3 天、面试前 1 天等 |
| 备注1 | 混合 | 长文本 | 投递限制、志愿规则、官方提示 |
| 备注2 | 咨询复盘 | 长文本 | 导师策略判断、复盘、后续调整 |

## 推荐逻辑

- P0: 用户证据强、城市匹配、岗位方向清晰、银行库入口可核验。
- P1: 有较强匹配，但竞争强或岗位细节需核验。
- P2: 政策行、总行或高竞争岗位，适合低成本冲刺。
- P3: 入口或岗位不清、城市不匹配、用户偏好冲突，先观察。
- 放弃: 用户明确排斥岗位性质、地点、营销/柜面/基层或签约风险不可接受。

## Gotchas

- 不要把底库所有银行无差别塞进用户表；用户表必须经过筛选。
- 不要把长 JD 放进主表，主表只放摘要和链接。
- 不要把日期写成文本；能确定日期时必须转日期类型。
- 不要因为外部文档不支持提醒就省略提醒字段；至少保留 `提醒日期` 和 `下一动作`。
- 不要把 `投递优先级` 和 `同类梯队` 混为一谈；前者是对用户的定制判断，后者是银行事实标签。
