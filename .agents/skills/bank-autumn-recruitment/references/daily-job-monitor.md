# 每日岗位巡检自动化

当用户要求“每天固定时间搜索岗位”“自动更新投递表”“监控优质信息源”时，使用本规范。目标是让 Codex 自动化每天巡检新放出的校招岗位，整理进用户的秋招投递表，并触发邮件提醒。

## 默认运行方式

- 默认频率: 每天 09:00。
- 默认时区: 用户所在地时区；本仓库场景默认 `Asia/Shanghai`。
- 默认对象: 2027 届银行通用校招；只巡检用户选择的投递类别。
- 默认表格: 用户确认后的在线工作台 `2027 届银行秋招投递工作台`；在线文档工具不可用时保留 Markdown 预览并提示用户连接工具。
- 默认输出: 新增岗位表、待用户确认清单、邮件提醒发送结果、今日处理提醒、需要用户补充的信息。

用户没有指定时间时，用默认时间；用户指定时间时以用户为准。

## 信息源分层

优先级从高到低：

1. 银行官方招聘官网、总行/分行官网、银行官方公众号公告。
2. 学校就业网、院系就业通知、宣讲会/双选会页面。
3. 主流校招平台和社区，如牛客、应届生求职网、实习僧、Boss/猎聘校招频道等。
4. 经验贴、社群转发、博主整理表，只能作为线索，必须回到官方或平台链接核验。

不要把二手整理表当作事实来源。无法确认的岗位可以写入表格，但用户可见字段必须标 `待用户确认`。

## 搜索关键词

默认组合：

- `2027届 银行 校园招聘`
- `2027届 银行 秋招提前批`
- `银行 2027届 管培 金融科技 数据分析`
- `总行 分行 金融科技 校招 2027届`
- `银行 官方招聘 2027届 校招`
- `公司名 2027届 银行 校园招聘`

根据用户目标城市、行业或公司池追加关键词。

具体到每个投递类别的信息源、重点银行池和关键词，读取 `role-source-catalog.md`。每日巡检必须先确认用户选择的投递类别，再只使用对应类别的信息源策略。

## 银行巡检范围

默认纳入这些银行校招岗位族：

- 总分行管培、管理培训生、综合培养生。
- 金融科技、科技菁英、软件开发、系统运维、数字化转型。
- 数据分析、经营分析、商业分析、风险数据、BI。
- 产品经理、数字银行产品、互联网金融产品、渠道产品。
- 运营管理、渠道运营、零售运营、平台运营。
- 风险合规、授信审批、内控合规、法律合规、反洗钱。
- 客户经理、财富顾问、零售金融、对公客户经理。
- 柜面、综合柜员、运营支持、营业网点服务。

## 入表规则

只新增或更新与用户已选择投递类别相关的岗位。银行通用校招场景下，先按 `role-source-catalog.md` 生成类别关键词，再结合城市、公司池和官方来源巡检；如果用户明确排除柜面、营销、异地分行或技术岗，巡检时按用户偏好过滤。

每条岗位至少尝试填写：

| 字段 | 自动化填写规则 |
|---|---|
| 更新日期 | 巡检当天日期 |
| 公司名称 | 从官方标题或来源页提取 |
| 校招类型 | 按标题/公告判断；不确定填 `待用户确认` |
| 投递通道 | 银行招聘官网/学校就业网/校招平台/内推/官方公众号 |
| 官方标题 | 原公告标题或页面标题 |
| 岗位名称 | 目标岗位名；无法确定填 `待筛选` |
| 投递类别 | 用户选择的类别；多类别命中时填最主要类别 |
| 岗位族 | 总分行管培/金融科技/数据分析/产品经理/运营管理/风险合规/客户经理/营销/柜面/综合服务 |
| 匹配等级 | 默认 `待判断`，有用户画像时再判高/中/低/保底 |
| 来源链接 | 原始链接 |
| 截止日期 | 找不到就填 `待用户确认`；日期列落表时留空 |
| 城市 | 找不到就填 `待用户确认` |
| 状态 | 新增默认 `待用户确认` |
| 下次跟进日 | 新增默认次日；临近截止按提醒规则提前 |
| 提醒级别 | 截止不明为 `本周`；临近截止为 `今日处理` 或 `3天内` |
| 邮件提醒状态 | 新增可投或截止临近时填 `待发送`，无需提醒填 `无需发送` |
| 邮件提醒原因 | 新增可投/截止临近/今日处理 |
| 上次邮件时间 | 成功发送后写入真实发送时间 |
| 下一动作 | 获取官方链接/确认截止日期/筛选岗位/投递 |
| 复盘记录 | 写入线索来源和待用户确认事项 |

## 去重与更新

判定同一岗位的优先顺序：

1. 来源链接完全相同。
2. 公司名称 + 官方标题相同。
3. 公司名称 + 岗位名称 + 投递类别 + 校招类型 + 城市高度相似。

发现重复时不要新增行，更新已有行的 `更新日期`、`来源链接`、`截止日期`、`状态`、`下次跟进日` 或 `复盘记录`。

## 邮件提醒触发

每次巡检结束后，读取 `email-reminders.md` 执行邮件提醒：

- 对新增且可投递的岗位发送 `新增可投岗位` 邮件。
- 对截止日期 3 天内、状态为待用户确认/未投的岗位发送 `截止临近` 邮件。
- 同一岗位、同一提醒原因当天只发送一次。
- 邮件发送成功后回写 `邮件提醒状态=已发送` 和 `上次邮件时间`。
- 没有邮箱发送工具或收件邮箱时，不声称已发送；将 `邮件提醒状态` 设为 `发送失败`，并提示用户连接邮箱工具或补充邮箱。

## 自动化输出摘要

每次自动巡检完成后输出：

```markdown
## 今日巡检摘要

事实:
- 巡检时间: ...
- 巡检方向: 银行通用校招
- 新增岗位: ... 个
- 更新岗位: ... 个
- 邮件提醒: 已发送 ... 封 / 待处理 ... 封

建议:
- 今日处理: ...
- 3天内处理: ...
- 本周观察: ...

待用户确认:
- 截止日期待用户确认: ...
- 官方链接待用户确认: ...
- 岗位城市待用户确认: ...
- 邮件发送失败: ...
```

如果没有新增岗位，也要输出“今日无新增”，并列出已临近截止或需要跟进的旧岗位。

## 自动化边界

- 不承诺覆盖全部岗位。
- 不编造岗位、截止日期、薪资、HC、城市或开放状态。
- 不自动替用户投递。
- 不修改用户已明确标为放弃/拒绝/offer 的记录，除非用户要求。
- 如果网络、登录态或目标平台限制访问，输出受限来源和下一步建议。
