# 银行方向秋招陪跑 Demo

首版 Demo 默认服务 `2027 届银行通用校招`。目标不是替用户做最终职业判断，而是先把银行校招拆成可验证的岗位族、投递表和每日跟进节奏。

## 最少背景信息

背景不足时，只追问会影响匹配和投递表的信息：

- 投递岗位类别: 从银行岗位族里选择 1-3 个主投递类别。
- 学历、年级、毕业届别、专业、学校层次。
- 实习、项目、科研、竞赛、社团、证书和工具能力。
- 目标城市或区域，是否接受分行/异地/轮岗。
- 对稳定性、成长性、回报、城市的权重。
- 每周可投入秋招准备的时间。
- 是否已有简历、已投岗位、笔试/面试/offer 状态。

如果用户只给了“2027 届，想投银行”，先按 `待补背景` 生成岗位族假设和 Markdown 追踪表预览，不要阻塞建表；用户确认后再创建在线文档。

## 投递类别选择

首次使用 Skill 时，先让用户选择 1-3 个投递类别。推荐输出为：

```markdown
先选你要重点巡检和投递的类别，建议最多选 3 个，后续每日巡检只会围绕这些类别入表：

| 类别 | 适合人群 | 典型岗位 |
|---|---|---|
| 总分行管培 | 想走综合培养、轮岗、管理路径 | 管理培训生、综合培养生 |
| 金融科技 | 有技术/数字化/系统项目证据 | 金融科技岗、科技菁英、数字化转型 |
| 数据分析 | 有数据、建模、经营分析能力 | 数据分析、经营分析、商业分析、BI |
| 产品经理 | 有产品、需求、用户研究经验 | 数字银行产品、渠道产品、金融产品 |
| 运营管理 | 有运营、流程、活动、项目推进经历 | 零售运营、渠道运营、平台运营 |
| 风险合规 | 金融/法律/统计/风控相关 | 风险管理、授信审批、内控合规 |
| 客户经理/营销 | 接受客户经营和业绩压力 | 对公/零售客户经理、财富顾问 |
| 柜面/综合服务 | 更看重稳定、城市和确定性 | 综合柜员、运营支持、网点服务 |
```

如果用户已经明确目标，如“只投管培和风控”，不要重复要求选择；直接确认类别并继续。

## 银行岗位族

| 岗位族 | 常见名称 | 更看重的证据 | 常见风险 |
|---|---|---|---|
| 总分行管培 | 管理培训生、综合培养生、总行管培、分行管培 | 学校背景、综合素质、表达、实习、学生工作、竞赛、稳定动机 | 轮岗和分配不确定，岗位内容可能泛 |
| 金融科技 | 金融科技岗、科技菁英、软件开发、系统运维、数字化转型 | 编程、数据、系统、产品技术项目、金融科技实习 | 技术考察强，非技术背景需谨慎 |
| 数据分析 | 数据分析、经营分析、商业分析、风险数据、BI | SQL/Python/Excel、指标分析、建模、数据项目、业务理解 | 岗位名可能分散在科技、风控、零售条线 |
| 产品经理 | 产品经理、数字银行产品、互联网金融产品、渠道产品 | 需求分析、用户研究、产品设计、数据复盘、跨部门推进 | 银行产品岗数量少，常和科技/运营混合 |
| 运营管理 | 运营管理、渠道运营、零售运营、用户运营、平台运营 | 活动运营、用户增长、流程优化、数据看板、执行复盘 | 容易和营销/柜面混淆，需要核验岗位说明 |
| 风险合规 | 风险管理、授信审批、内控合规、法律合规、反洗钱 | 金融、法律、统计、风控模型、审慎细致、政策理解 | 笔试和专业面更偏金融法规或数理 |
| 客户经理/营销 | 客户经理、财富顾问、零售金融、对公客户经理 | 沟通、抗压、销售服务、金融证书、当地资源或城市稳定性 | 业绩压力和客户维护强，需要确认真实工作内容 |
| 柜面/综合服务 | 综合柜员、运营支持、营业网点服务 | 细致、服务意识、稳定性、合规意识、城市匹配 | 职业路径和转岗空间需提前核验 |

## 匹配等级

| 匹配等级 | 判断标准 | 行动 |
|---|---|---|
| 高匹配主攻 | 用户已有强证据，岗位要求和经历高度重合，准备成本低 | 优先进入追踪表预览，准备岗位版简历，尽快投递 |
| 中匹配冲刺 | 有部分证据，但需要补银行理解、项目表达或笔面试能力 | 小批量投递，边投边补材料和面试故事 |
| 低匹配探索 | 兴趣强但证据弱，或岗位真实内容不清 | 少量投递/信息面/岗位研究验证，不占主资源 |
| 保底稳妥 | 城市、门槛、岗位要求或竞争强度相对可控 | 维持风险底盘，避免只投少量高竞争岗位 |

## 默认匹配逻辑

- 金融、经济、管理、会计、法律背景: 优先看管培、风险合规、客户经理/营销、运营管理；有数据项目时可冲数据分析。
- 计算机、软件、信息、数学、统计背景: 优先看金融科技、数据分析、数字化产品；同时保留管培或运营管理。
- 有产品/运营/数据实习: 优先看数字银行产品、运营管理、数据分析、金融科技产品方向。
- 城市稳定性强: 分行、当地城商行、农商行、网点/运营支持可作为保底稳妥；总行和金融科技岗作为冲刺或主攻。
- 稳定性权重大: 国有大行、政策性银行、股份行分行、城商行可提高优先级。
- 成长性权重大: 总行、金融科技子公司、数字化部门、数据/产品相关岗位可提高优先级。

## 银行校招节奏

银行批次和日期每年变化明显，必须实时核验。无法核验时只写阶段，不写具体日期。

| 阶段 | 目标 | 动作 |
|---|---|---|
| 预热期 | 建岗位池和材料底座 | 背景诊断、银行岗位族排序、主版本简历、证书/笔试准备 |
| 提前批 | 验证银行岗位匹配 | 投高匹配主攻和中匹配冲刺，记录网申与测评反馈 |
| 正式批 | 扩大有效投递 | 批量维护追踪表，按截止日期、状态和下次跟进日推进 |
| 笔面试期 | 提升转化率 | 准备行测/英语/金融常识/半结构化/无领导/业务面 |
| 体检签约 | 控制签约风险 | 核验三方、违约、户口、轮岗、分配、试用期和录用条件 |
| 补录尾声 | 降低秋招风险 | 补保底岗位，追流程，比较 offer 与继续等机会的成本 |

## 默认输出顺序

1. 背景诊断卡。
2. 银行岗位匹配矩阵。
3. Markdown 追踪表预览；用户确认后创建在线文档。
4. 今日/本周投递提醒。
5. 需要实时核验的岗位、批次、截止日期和链接。
