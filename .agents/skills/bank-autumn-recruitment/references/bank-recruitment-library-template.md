# 银行秋招投递库模板

用于维护“所有银行的秋招投递库”。本文件只定义模板和待办，不收集实时信息；正式采集时必须回到官方招聘页、银行官网、官方公众号、学校就业网或可信校招平台核验。

## 设计目标

- 苦活: 维护银行库、官方招聘网站、网申入口和最近一年招聘公告。
- 巧活: 把职业咨询导师基于学生简历做投递策略的经验，沉淀成可复用的判断规则、案例和推荐逻辑。
- Demo 优先: 先用主流银行填骨架，找不到的字段快速跳过，确认结构后再深采公告和岗位。

## 银行主档案

只保留以下字段。

| 字段 | 说明 | 示例/填写规则 |
|---|---|---|
| 银行名称 | 银行标准名称 | 中国建设银行 |
| 银行类型 | 政策性银行/国有六大行/股份制银行/城商行/农商行/外资行 | 国有六大行 |
| 总部城市 | 总部所在地 | 北京 |
| 梯队 | 同类型银行内相比，不做跨类型绝对排名 | 国有大行-T1、股份行-T1、城商行-T2 |
| 官方招聘网站 | 银行官方招聘站或官网招聘栏目 | 必须优先官方 |
| 网申入口 | 可直接投递或登录的入口 | 找不到写 `待用户确认` |

## 年度招聘公告档案

默认只收集最近一年。每家银行先保留一条最近届别/最近年度公告记录；找不到公告细项时跳过，不追旧年份。

| 字段 | 说明 | 示例/填写规则 |
|---|---|---|
| 银行名称 | 关联银行主档案 | 中国建设银行 |
| 最近届别/年度 | 最近可见校招届别或年份 | 2026 届 |
| 招聘批次 | 秋招提前批/秋招正式批/补录/春招/暑期实习 | 校园招聘 |
| 公告标题 | 官方公告原题 | 找不到写 `待用户确认` |
| 公告链接 | 官方公告 URL | 找不到写招聘网站入口 |
| 发布日期 | 公告发布日期 | 找不到写 `待用户确认` |
| 网申截止日 | 网申截止日期 | 找不到写 `待用户确认` |
| 采集状态 | 已确认/部分确认/待用户确认 | 部分确认 |

## 岗位信息档案

岗位信息属于第二阶段采集。不同分行、总行、子公司、城市、岗位类别必须拆成不同记录。

| 字段 | 说明 | 示例/填写规则 |
|---|---|---|
| 银行名称 | 关联银行主档案 | 招商银行 |
| 最近届别/年度 | 关联年度公告 | 2026 届 |
| 岗位名称 | 官方岗位名 | 金融科技岗 |
| 岗位类别 | 管培/金融科技/数据分析/风控/运营/客户经理/柜面等 | 金融科技 |
| 总行/分行/子公司 | 组织归属 | 上海分行 |
| 工作地点 | 城市或区域 | 上海 |
| 适合画像 | 咨询经验沉淀后的学生画像 | 技术/数据背景，接受银行科技条线 |
| 投递建议 | P0/P1/P2/P3 及理由 | P1: 岗位匹配但竞争强 |
| 来源链接 | 岗位或公告 URL | 必须核验 |
| 确认状态 | 已确认/待用户确认/过期 | 待用户确认 |

## 咨询经验蒸馏待办

先记录，不在 Demo 阶段实现训练或收集真实咨询数据。

- [ ] 收集职业咨询导师常用判断维度: 学历、专业、实习、项目、证书、地域、性格偏好、风险承受。
- [ ] 沉淀“简历画像 -> 银行类型内梯队 -> 岗位类别 -> 投递优先级”的规则。
- [ ] 建立典型学生画像样例: 金融强背景、理工转金融科技、普通本科稳妥型、地域绑定型、无实习补救型等。
- [ ] 设计咨询记录脱敏结构: 用户背景、简历证据、咨询建议、后续反馈、最终结果。
- [ ] 明确隐私和授权规则: 不采集姓名、手机号、身份证，学校可泛化，经历细节可脱敏。
- [ ] 后期用脱敏咨询数据反向修正评分权重、投递策略和岗位匹配规则。
- [ ] 建立“导师可编辑规则库”，让职业咨询师能手动补充经验，不依赖一次性训练。

## Demo 采集顺序

1. 先补主流银行主档案: 政策性银行、国有六大行、全国性股份制银行、代表性城商行/农商行。
2. 每家只补最近一年招聘公告；不追多年份历史。
3. 主档案跑通后，再采集岗位信息。
4. 所有日期、链接、岗位名称只从官方或可信来源录入；经验贴只能写进备注或后续研究材料。
