# 外部投递表后的自动化陪跑

当用户已经确认投递表并创建 Notion、腾讯文档、飞书表格、Google Sheets 或 Excel 链接后读取本文件。目标不是制造很多提醒，而是让用户不会错过截止、流程进展、公告更新和关键复盘。

默认先交付对话内提醒摘要，不直接写回 Notion、不发送邮件、不创建外部提醒。用户确认摘要和回写建议后，再进入真实外部动作。

## 必要自动化

只默认建议 4 类自动化:

| 自动化 | 频率 | 读取对象 | 触发条件 | 输出 |
|---|---|---|---|---|
| 截止日提醒 | 每天早上 | 投递表 | `截止时间` 在 7/3/1 天内，且状态不是 offer/拒绝/放弃 | 截止银行、优先级、下一动作、是否今日必须处理 |
| 已投递进度信源巡检 | 每天傍晚 | 投递表 + 公开信源 | 状态为已投/测评/笔试/面试/体检 | 是否出现同银行同批次通知线索，提醒查邮箱/短信/站内信 |
| 官方公告巡检 | 每天上午 | 银行库官方招聘网站 + 投递表链接 | 新公告、新岗位、截止日或入口变化 | 新增公告摘要、岗位选择建议、是否触发简历定制 |
| 周复盘与 Offer 决策 | 每周一次 | 投递表全量 | 一周投递和流程变化；出现 offer 或准 offer | 下周行动清单、策略调整、Offer 决策表 |

## 对话内提醒摘要

四类自动化的第一版统一输出为一份 Markdown 摘要:

```bash
python3 scripts/conversation_reminder_summary.py --input rows.json --today 2026-06-16 --output conversation-summary.md
```

摘要固定包含:

- `截止日提醒`: 7/3/1 天内截止、且未进入 offer/拒绝/放弃的岗位。
- `网申陪跑`: 已有公告链接或网申入口、状态仍为待用户确认/未投的岗位。
- `流程线索巡检`: 已投、测评、笔试、面试、体检中的岗位，只列出需要查官方通知和社区弱线索的对象。
- `周复盘`: 按状态汇总当前表，给下周优先处理方向。
- `待用户确认`: 缺截止时间、官方链接或网申入口的岗位。

该摘要只读表格，不代表已经完成外部检索；社区线索必须另行联网核验，且只能作为弱线索。

## 信源优先级

1. 银行官方招聘网站、官方校招专题页、官方公众号原文。
2. 学校就业网、宣讲会页面、官方合作招聘平台。
3. 牛客、应届生等求职社区的流程帖。
4. 小红书、社群截图、匿名爆料。

第三、四类只能作为流程线索，不能写成事实。提醒中必须分成 `可靠事实` 和 `弱线索`。

## 字段依赖

外部表至少要有:

- `银行名称`
- `投递优先级`
- `投递状态`
- `截止时间`
- `投递日期`
- `官方招聘网站`
- `网申入口`
- `公告链接`
- `下一动作`
- `提醒日期`
- `提醒状态`

未知日期留空，不要填文本占位。无法自动读取日期时，把任务放入 `待用户确认` 清单，提醒用户人工补齐。

## 本地 dry-run 测试

在连接 Notion、邮箱或定时自动化前，先用本地脚本验证提醒逻辑，不做任何外部写入:

```bash
python3 scripts/automation_dry_run.py --input rows.json --today 2026-06-15 --output automation-dry-run.md
```

dry-run 输出:

- `今日处理`: 截止 1 天内或提醒日期已到的岗位。
- `截止提醒`: 截止 7 天内的岗位。
- `邮件待发送`: 理论上应发邮件的提醒，但标明 `dry-run: 未发送`。
- `待用户确认`: 缺截止时间、链接或岗位细节的记录。

只有 dry-run 摘要合理，且用户确认连接外部工具后，才创建真实提醒或发送邮件。

邮件提醒需要再生成邮件草稿:

```bash
python3 scripts/generate_email_reminders.py --input rows.json --today 2026-06-15 --recipient user@example.com --output email-draft.md
```

该脚本只生成草稿和回写建议，不发送真实邮件。真实发送必须等用户确认草稿、收件邮箱明确、邮箱工具可用之后再做。

## 截止提醒规则

- 截止 7 天内: 提醒准备岗位版简历和材料。
- 截止 3 天内: 提醒完成网申或明确放弃。
- 截止 1 天内或当天: 标为今日必须处理。
- 已投、offer、拒绝、放弃不再走未投提醒。
- 没有截止日的 P0/P1 岗位，每周至少提醒一次核验。

## 进度信源巡检规则

只巡检用户已经投递或进入流程的岗位，避免信息过载。

输出格式:

- `可靠事实`: 官方公告、学校就业网、银行短信/邮件截图等可核验信息。
- `弱线索`: 求职社区或小红书出现同批次通知讨论。
- `建议动作`: 查邮箱、查短信、查站内信、准备笔试、准备面试、继续等待或补投同类岗位。

不要因为有人晒通知就断言用户被刷；只能提示“同批次可能开始发通知”。

## 官方公告巡检规则

公告巡检只看银行库和投递表中已有银行，除非用户要求扩展银行池。

发现公告后要输出:

1. 公告标题和官方链接。
2. 招聘对象、岗位方向、城市/机构、截止时间。
3. 和用户画像匹配的岗位优先级。
4. 需要新增或更新到投递表的字段。
5. 是否进入 `announcement-resume-tailoring.md` 做岗位版简历和网申细节。

## Gotchas

- 不要把所有银行每天都扫一遍后输出长清单；默认只提醒对用户当前表有动作价值的变化。
- 不要把小红书和社群消息当作官方进度。
- 不要在日期为空时自动猜截止日。
- 不要只创建 Notion 原生提醒；Skill 也要能读表二次提醒。
- 不要提醒已经 offer/拒绝/放弃的岗位继续投递。
