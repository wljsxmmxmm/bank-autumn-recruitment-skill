# Notion 工作台创建协议

当用户确认 Markdown 预览并要求创建 Notion 表时，使用本文件。Notion 表是银行秋招 Skill 的长期主操作台；Markdown 只是创建前预览和用户确认材料。

## 创建流程

1. 确认用户已认可银行清单、优先级和核心字段；未确认前不要创建 Notion。
2. 创建或更新一个 Notion 数据库，标题建议为 `2027 届银行秋招投递工作台｜{目标城市}`。
3. 按本文件的主表 schema 建字段；Markdown 预览、脚本输出和 Notion 主表使用同一套字段。
4. 无法确认的日期留空，无法确认的事实写入 `下一动作`、`主要风险` 或备注。
5. 创建固定视图: `Default view`、`P0主攻`、`本周处理`、`流程中`、`截止日历`、`提醒日历`、`结果复盘`。
6. 创建成功后返回 Notion URL，并说明创建成功后的 Notion URL 是后续维护、提醒、复盘的主入口。
7. 创建失败或字段/视图未建成功时，不要声称已完成；说明缺口并保留本地 Markdown 预览。

## 主表字段

| 字段 | 类型 | 选项或规则 |
|---|---|---|
| 银行名称 | Title | 银行/机构/分行机会名；同银行不同地区、总分行、子公司、岗位要拆行 |
| 总行/分行 | Select | 总行、分行、子公司、直属机构、待用户确认；具体城市或机构名可写入备注 |
| 推荐岗位方向 | Multi-select | 总分行管培、金融市场、公司金融、运营管理、金融科技、数据分析、风控、综合 |
| 银行类型 | Select | 政策性银行、国有六大行、股份制银行、城商行、农商行 |
| 同类梯队 | Select | 政策性-T0、政策性-T1、国有大行-T0、国有大行-T1、股份行-T0、股份行-T1、股份行-T2、城商行-T0、城商行-T1、城商行-T2、农商行-T0、农商行-T1、农商行-T2 |
| 投递优先级 | Select | P0主攻、P1重点、P2冲刺、P3观察、放弃 |
| 投递批次 | Select | 校园招聘、秋招提前批、秋招正式批、补录、春招、暑期实习 |
| 开始时间 | Date | 已确认才填；未知留空 |
| 截止时间 | Date | 已确认才填；未知留空 |
| 投递日期 | Date | 用户完成投递后填写 |
| 官方招聘网站 | URL | 官方招聘主页 |
| 网申入口 | URL | 可直接投递入口 |
| 公告链接 | URL | 官方公告、校招专题或可信公告页 |

| 三面/终面 | Text | 待通知、已完成或具体时间说明 |

| 备注2 | Text | 策略判断、复盘、后续调整 |

## 统一字段协议

- Markdown 预览、`scripts/generate_tracking_table.py` 和 Notion 主表必须共用上面的字段名。
- 不再维护 `梯队`、`优先级`、`网申截止日` 这类旧字段名；进入脚本前就整理成主表字段。
- 旧字段里的内容需要在进入脚本前整理成主表字段；不要在脚本文档里长期维护第二套字段。
- `同类梯队` 的 T0/T1/T2 是同类型内部相对标签，不做跨类型绝对排名。
- `政策性-T0`、`国有大行-T0` 是预留给总行、核心专项、极高竞争机构或后续细分的选项；默认机会池可以先用 `政策性-T1`、`国有大行-T1`。

## 固定视图

| 视图 | 类型 | 规则 |
|---|---|---|
| Default view | Table | 展示主字段；按 `投递优先级` 升序 |
| P0主攻 | Table | 筛选 `投递优先级 = P0主攻` |
| 本周处理 | Table | 优先展示 `待用户确认`、`未投`、临近提醒和下一动作 |
| 流程中 | Board | 按 `投递状态` 分组 |
| 截止日历 | Calendar | Calendar by `截止时间` |
| 提醒日历 | Calendar | Calendar by `提醒日期` |
| 结果复盘 | Table | 筛选 `offer`、`拒绝`、`放弃` |

## 创建后检查

- 日期字段必须是真 Date，未知日期留空，不要填 `待用户确认`。
- URL 字段只能填真实 URL；不确定时写到备注或下一动作。
- `待用户确认` 是事实状态，不是失败；用来暴露还没被官方来源确认的信息。
- Notion 表创建成功后，后续公告更新、截止提醒、周复盘、Offer 决策都优先读写这张表。
