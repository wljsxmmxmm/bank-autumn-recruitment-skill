# 轻量交互入口

当用户只表达“想做银行秋招规划/陪跑/从零开始”，但没有给足背景时，先给一个菜单，不要直接输出长篇规划。

如果用户已经给出学历、目标城市、岗位偏好、实习和证书等关键背景，可以跳过入口菜单，直接进入评估、策略或投递表。

## 入口菜单

```markdown
你现在想先做哪一步？

A. 先评估我的银行秋招竞争力
B. 先制定投递策略和银行池
C. 我已经有公告/JD，帮我选岗位和定制简历
D. 我已经进入笔试/面试/Offer 阶段

说明：我不会编招聘信息。未确认的开放状态、截止日、岗位名和链接都会标为 `待用户确认`。
```

## 分支问题

每次最多问 1-3 个问题；优先用选项，必要时让用户补充自由文本。

### A. 竞争力评估

先要这些信息：

```markdown
为了评估得准，你可以二选一：

A. 上传或粘贴简历，我先解析，再追问缺失信息
B. 按自述模板介绍自己，我根据模板评估

自述模板:
1. 教育背景：本科/硕士学校层次、专业、毕业届别、成绩/排名
2. 目标方向：城市、银行类型、岗位方向、是否排斥柜面/营销
3. 经历材料：实习、证书、项目、校园经历、职业约束
```

用户补齐后读取 `resume-competitiveness.md`，输出六维评分和短板。

### B. 投递策略和银行池

先问：

```markdown
你更想按哪种方式建第一版银行池？

A. 稳妥优先：提高进面和 offer 概率
B. 平衡型：主攻匹配岗位，同时保留冲刺项
C. 冲刺优先：总行、金融市场、政策行和高竞争管培多一些
```

然后结合城市、岗位偏好、是否排斥柜面/营销，读取 `bank-tier-strategy.md` 和 `application-tracker.md`。

### C. 公告/JD 定制

先让用户贴公告、JD 或链接。没有官方来源时，字段写 `待用户确认`，不要把二手信息当事实。

### D. 笔试/面试/Offer

根据用户阶段读取对应参考：

- 笔试、测评、无领导、半结构化、结构化: `exam-interview-guidance.md`
- 意向、体检、签约、多个 offer: `offer-decision-framework.md`

## 输出规则

- 信息不足时先菜单，不急着分析。
- 信息足够时直接做事，不机械追问。
- 用户选择后，只推进当前分支；不要一次把全流程都展开。
- 需要表格时仍必须使用 `scripts/generate_tracking_table.py` 生成 Markdown 预览。
- 未确认项统一写 `待用户确认`。
