# 外部在线文档转换规则

当用户确认 Markdown 银行投递表后，需要转为腾讯文档、飞书表格、Google Sheets 或本地 Excel 时读取本文件。Notion 主操作台以 `references/notion-workspace-schema.md` 为准；本文件只保留跨平台转换规则和 Notion 兜底提示。

## 通用流程

1. 先保留 Markdown 预览，用户确认字段和银行清单。
2. 选择目标平台: Notion / 腾讯文档 / 飞书表格 / Google Sheets / Excel。
3. 如果目标是 Notion，停止使用本文件，改读 `references/notion-workspace-schema.md`。
4. 如果目标是其他表格平台，沿用 Notion 工作台字段名创建外部表格，优先使用真实日期、单选、多选、URL、长文本类型。
5. 创建默认视图或筛选: P0主攻、本周处理、截止临近、流程中、笔面试日程、结果复盘。
6. 设置提醒字段: `提醒日期`、`提醒状态`、`下一动作`。
7. 创建成功后回写外部文档 URL；不要在工具调用成功前声称已创建。
8. 外部链接创建成功后，读取 `automation-playbook.md`，建议创建截止提醒、已投递进度巡检、官方公告巡检和周复盘自动化。

## 字段类型

| 字段 | 腾讯/飞书/Sheets/Excel 类型 | 规则 |
|---|---|---|
| 银行名称 | 文本 | 主键字段 |
| 总行/分行 | 下拉单选/文本 | 总行、分行、子公司、直属机构、待用户确认 |
| 推荐岗位方向 | 下拉多选/文本 | 平台不支持多选时用逗号分隔文本 |
| 银行类型 | 下拉单选 | 固定枚举 |
| 同类梯队 | 下拉单选 | 使用 `notion-workspace-schema.md` 的同一组选项 |
| 投递优先级 | 下拉单选 | P0主攻/P1重点/P2冲刺/P3观察/放弃 |
| 投递批次 | 下拉单选/文本 | 平台不支持下拉时用文本 |
| 开始时间 | 日期 | 不要写成普通文本 |
| 截止时间 | 日期 | 支持排序、筛选、提醒 |
| 投递日期 | 日期 | 未投留空 |
| 官方招聘网站 | 超链接/URL文本 | 保留可点击链接 |
| 网申入口 | 超链接/URL文本 | 保留可点击链接 |
| 公告链接 | 超链接/URL文本 | 保留可点击链接 |
| 简历版本 | 下拉单选 | 银行业务版/城市分行版/金融市场冲刺版/政策行冲刺版/风控版 |
| 投递状态 | 下拉单选 | 待用户确认/未投/已投/测评/笔试/一面/二面/三面/终面/体检/offer/拒绝/放弃 |
| 笔试/一面/二面/三面/终面 | 文本 | 待通知、已完成或具体时间说明 |
| 推荐理由/主要风险/下一动作/备注1/备注2 | 长文本 | 保留换行 |
| 提醒日期 | 日期 | 截止前、笔面试前、投后跟进 |
| 提醒状态 | 下拉单选 | 待提醒/已提醒/无需提醒/提醒失败 |

## 日期和提醒规则

- `截止时间` 已知且状态为未投/待用户确认: `提醒日期 = 截止时间 - 3天`。
- `截止时间` 是今天或明天: `投递优先级` 不变，但 `提醒原因=截止临近`，视图进入 `截止临近`。
- `投递日期` 已填且 7 天无反馈: `提醒日期 = 投递日期 + 7天`，`提醒原因=投后跟进`。
- `笔试/面试` 有日期: `提醒日期 = 笔试/面试日期 - 1到3天`，`提醒原因=笔面试准备`。
- 状态为 offer/拒绝/放弃: `提醒状态=无需提醒`。
- 日期未知时，不编造日期；保留 `下一动作=核验截止日期/核验笔试时间`。

## 平台规则

### Notion

- Notion 不是通用表格导出目标，而是本 Skill 的主操作台。
- 创建 Notion 时必须读取 `references/notion-workspace-schema.md`，按固定主表字段和固定视图创建。
- 如果连接器不能设置某个视图或字段类型，说明缺口，不要把文本字段伪装成日期字段。

### 腾讯文档 / 飞书表格 / Google Sheets / Excel

- 用第一行作为表头，启用筛选。
- 日期列必须用日期格式，不要写文本占位；未知日期留空，另用备注或下一动作记录 `待用户确认`。
- 单选字段用数据验证下拉: 银行类型、同类梯队、投递优先级、投递状态、提醒状态。
- URL 字段保留完整链接，必要时另设展示文本。
- 用条件格式:
  - P0 标红或高亮。
  - 截止时间 3 天内标红。
  - 投递状态=offer 标绿，拒绝/放弃标灰。
- 如平台支持提醒/自动化，用 `提醒日期` 创建日程或通知；不支持时保留提醒字段，由邮件提醒模块读取。

## 导出/导入前检查

- 日期字段是否是真日期。
- 链接字段是否可点击或保留完整 URL。
- 下拉枚举是否与 Skill 中一致。
- 是否有 `提醒日期`、`提醒状态`、`下一动作`。
- 是否保留用户确认后的银行清单，没有自动加入未确认银行。
- 是否把 `待用户确认` 留在文本字段，而不是日期字段。

## Gotchas

- 不要把 Markdown 表原样复制到外部表格后就结束；字段类型才是可用性的关键。
- 不要在日期列填文本占位，这会破坏排序和提醒。
- 不要在外部文档创建失败时声称已创建。
- 不要让提醒只存在平台里；Skill 也要能通过 `提醒日期/提醒状态` 二次读取和发送邮件。
