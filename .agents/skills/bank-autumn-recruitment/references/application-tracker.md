# 秋招投递表格与提醒规范

这是首发 MVP 的核心功能。用户要求“生成秋招投递表”“做类似截图的校招表”“定期跟踪投递”时，优先读取本文件。银行秋招场景必须先生成 Markdown 预览，用户确认后再创建到用户常用在线文档。

## 核心原则

- 先生成 Markdown 预览，再做在线文档；表格是秋招操作台。
- 银行秋招追踪表必须使用 `scripts/generate_tracking_table.py` 生成，不接受 Agent 手写排序后的表格。
- 用户要求“尽可能全面”“覆盖大部分银行”“先给银行池”时，使用脚本内置 `comprehensive` 模板生成机会池骨架，再按用户城市、岗位类别和简历竞争力删减。
- 表头必须符合 `references/notion-workspace-schema.md` 的统一字段；同一家银行不同分行必须拆成多行。
- 当前岗位开放状态、截止日期、官方标题和投递链接必须联网核验或由用户提供来源；未确认写入 `下一动作`、`主要风险` 或备注，不要填进日期/URL 字段。
- 这是本 skill 的可信度亮点: 不编招聘信息，不把未确认的开放状态、日期、岗位名和链接说成事实。
- 不追求一次性填满所有岗位；先建可筛选、可复盘、可持续更新的表。
- 银行 Demo 默认覆盖银行通用校招，不只限产品/运营/数据。

## 银行秋招统一字段

| 字段 | 用途 | 填写规则 |
|---|---|---|
| 银行名称 | 银行或机构名称 | 同银行不同总行/分行/子公司/城市/岗位拆成独立行 |
| 总行/分行 | 机构层级 | 总行、分行、子公司、直属机构、待用户确认；具体机构名和城市可放备注 |
| 推荐岗位方向 | 岗位方向 | 总分行管培、金融市场、公司金融、运营管理、金融科技、数据分析、风控、综合 |
| 银行类型 | 政策性银行/国有六大行/股份制银行/城商行/农商行 | 不确定写 `待用户确认` |
| 同类梯队 | 同类型梯队 | 使用 `bank-tier-strategy.md` 和 `notion-workspace-schema.md` 的 Select 选项 |
| 投递优先级 | 投递顺序 | P0主攻/P1重点/P2冲刺/P3观察/放弃 |
| 投递批次 | 批次 | 校园招聘、秋招提前批、秋招正式批、补录、春招、暑期实习 |
| 开始时间 | 网申开始 | 已确认才填；未知留空 |
| 截止时间 | 网申截止 | 已确认才填；未知留空 |
| 投递日期 | 实际提交日期 | 未投留空 |
| 官方招聘网站 | 官方主页 | URL 字段，只填真实链接 |
| 网申入口 | 投递入口 | URL 字段，只填真实链接 |
| 公告链接 | 公告或专题页 | URL 字段，只填真实链接 |
| 简历版本 | 使用哪版简历 | 银行业务版/城市分行版/金融市场冲刺版/政策行冲刺版/风控版 |
| 投递状态 | 当前进度 | 待用户确认/未投/已投/测评/笔试/面试/体检/offer/拒绝/放弃 |
| 笔试 | 笔试/测评状态 | 待通知、已完成或具体时间说明 |
| 一面 | 一面状态 | 待通知、已完成或具体时间说明 |
| 二面 | 二面状态 | 待通知、已完成或具体时间说明 |
| 三面/终面 | 终面状态 | 待通知、已完成或具体时间说明 |
| 推荐理由 | 为什么值得投 | 用户背景、实习、证书、城市稳定性等匹配点 |
| 主要风险 | 最大不确定性 | 学历/专业/实习/笔试/地域/岗位真实内容/竞争强度 |
| 下一动作 | 下一步 | 核验公告/准备简历/完成网申/准备笔试面试/复盘 |
| 提醒日期 | 下次提醒日期 | 截止前、笔面试前或投后跟进日期 |
| 提醒状态 | 提醒进度 | 待提醒/已提醒/无需提醒/提醒失败 |
| 备注1 | 执行备注 | 机构/城市、志愿规则、岗位限制等 |
| 备注2 | 策略复盘 | 策略判断、复盘、后续调整 |

## 脚本使用

如果已有岗位候选列表，把列表整理为 JSON，再运行：

```bash
python3 scripts/generate_tracking_table.py --input rows.json --output tracking-preview.md
```

如果用户希望尽可能全面覆盖银行，先运行内置模板：

```bash
python3 scripts/generate_tracking_table.py --template comprehensive --output tracking-preview.md
```

该模板覆盖政策性银行、国有六大行、主要股份制银行、代表性城商行和农商行。模板是机会池骨架，不代表当年岗位已开放；`官方招聘网站`、`网申入口`、`公告链接`、`截止时间`、`笔试` 等必须继续确认。

输入可以是 JSON list，或包含 `rows` 的对象。示例：

```json
[
  {
    "银行名称": "中国建设银行",
    "总行/分行": "分行",
    "推荐岗位方向": "公司金融",
    "银行类型": "国有六大行",
    "同类梯队": "国有大行-T1",
    "投递优先级": "P0主攻",
    "投递批次": "秋招正式批",
    "开始时间": "",
    "截止时间": "",
    "投递日期": "",
    "官方招聘网站": "",
    "网申入口": "",
    "公告链接": "",
    "简历版本": "银行业务版",
    "投递状态": "未投",
    "笔试": "待通知",
    "一面": "待通知",
    "二面": "待通知",
    "三面/终面": "待通知",
    "推荐理由": "城市匹配强，有银行实习",
    "主要风险": "截止日和岗位说明待用户确认",
    "下一动作": "确认上海分行岗位、公告链接和截止时间",
    "提醒日期": "",
    "提醒状态": "待提醒",
    "备注1": "机构/城市：上海分行｜上海",
    "备注2": "城市匹配强"
  }
]
```

脚本会按 `投递优先级 -> 同类梯队 -> 银行名称` 排序，并输出与 Notion 主表一致的 Markdown 预览。字段缺失时留空；需要用户确认的事项写入 `下一动作`、`主要风险` 或备注。Agent 可以判断和补充候选岗位，但不能手写最终预览表。

全面模板生成后，必须提醒用户做二次筛选：

- 按目标城市保留本地城商行/农商行和目标分行。
- 按岗位类别保留管培、金融科技、数据分析、风控、运营、客户经理或柜面等主线。
- 对 P0/P1 银行优先核验官方招聘入口、开放批次和截止日期。
- 对不符合城市、学历、专业或工作偏好的银行标为 `观察` 或删除。

## 通用陪跑字段

非银行通用校招工作台可继续使用下列字段：

| 字段 | 用途 | 填写规则 |
|---|---|---|
| 更新日期 | 最近一次更新该岗位信息的日期 | 用真实日期；无法确认用 `待更新` |
| 公司名称 | 企业或机构名称 | 保持简称一致，便于筛选 |
| 校招类型 | 批次分类 | 暑期实习/秋招提前批/正式批/补录/春招/实习转正 |
| 投递通道 | 从哪里投 | 官网/学校就业网/校招平台/内推/宣讲会/公众号 |
| 官方标题 | 官方公告标题 | 优先使用官方原题；未确认标 `待用户确认` |
| 岗位名称 | 具体岗位 | 如产品经理、数据分析、后端开发、管培生 |
| 投递类别 | 用户选择的巡检类别 | 总分行管培/金融科技/数据分析/产品经理/运营管理/风险合规/客户经理/营销/柜面/综合服务 |
| 岗位族 | 便于横向管理 | 技术研发/产品运营/数据分析/设计内容市场/职能管培 |
| 匹配等级 | 投递优先级 | 高匹配主攻/中匹配冲刺/低匹配探索/保底稳妥 |
| 来源链接 | 投递或公告链接 | 没有链接时写来源说明和 `待用户确认` |
| 截止日期 | 网申截止 | 不确定则填 `待用户确认`，不要猜 |
| 城市 | 工作或面试城市 | 多城市可写主要城市或“全国/多地” |
| 状态 | 当前进度 | 待用户确认/未投/已投/笔试/面试/offer/拒绝/放弃 |
| 下次跟进日 | 提醒依据 | 已投后默认 7 天；临近截止提前 3 天 |
| 提醒级别 | 行动紧急度 | 今日处理/3天内/本周/观察/无需提醒 |
| 邮件提醒状态 | 邮件发送进度 | 待发送/已发送/无需发送/发送失败 |
| 邮件提醒原因 | 为什么发邮件 | 新增可投/截止临近/今日处理/发送失败 |
| 上次邮件时间 | 防重复发送 | 每次成功发送后写入真实发送时间 |
| 下一动作 | 下一步操作 | 获取链接/改简历/投递/准备笔试/追进度/复盘 |
| 复盘记录 | 每次更新后的结论 | 记录拒绝原因、卡点、面试反馈、材料调整 |

## 银行 Demo 字段建议

银行方向建表时，字段保持通用结构，但下列选项要优先出现：

- 投递类别: 总分行管培、金融科技、数据分析、产品经理、运营管理、风险合规、客户经理/营销、柜面/综合服务。
- 岗位族: 默认和投递类别一致；岗位横跨多类时可多选。
- 校招类型: 秋招提前批、正式批、补录、暑期实习、实习转正、春招。
- 投递通道: 银行招聘官网、总行/分行官网、学校就业网、校招平台、官方公众号、宣讲会、内推。
- 状态: 待用户确认、未投、已投、测评/笔试、面试、体检、offer、拒绝、放弃。
- 邮件提醒状态: 待发送、已发送、无需发送、发送失败。
- 邮件提醒原因: 新增可投、截止临近、今日处理、发送失败。
- 下一动作: 核验公告、确认分行/城市、准备银行版简历、完成网申、准备测评/笔试、准备半结构化/无领导、面后复盘、核验签约规则。

银行岗位的 `官方标题`、`来源链接`、`截止日期`、`城市/分行`、`岗位归属条线` 必须尽量回到官方招聘页或可信平台确认。无法确认时写 `待用户确认`。

## 颜色与标签建议

- 校招类型:
  - 秋招提前批: 橙色
  - 正式批: 黄色
  - 暑期实习: 绿色
  - 补录/春招: 蓝色
  - 实习转正: 紫色
- 状态:
  - 待用户确认/未投: 灰色
  - 已投/笔试/面试: 蓝色
  - offer: 绿色
  - 拒绝/放弃: 红色或灰色
- 提醒级别:
  - 今日处理: 红色
  - 3天内: 橙色
  - 本周: 黄色
  - 观察: 蓝色
  - 无需提醒: 灰色

## 提醒规则

默认用这些规则生成 `提醒级别` 和 `下一动作`：

- 截止日期已过且状态是未投/待用户确认: `今日处理`，下一动作是确认是否还能投。
- 截止日期 3 天内且未投: `今日处理`，下一动作是完成投递或放弃。
- 截止日期 7 天内且未投: `3天内`，下一动作是准备对应简历版本。
- 已投超过 7 天无反馈: `本周`，下一动作是查流程、补投同类岗位或复盘简历。
- 进入笔试/面试: `今日处理` 或 `3天内`，下一动作是专项准备和面后复盘。
- 已 offer/拒绝/放弃: `无需提醒`，下一动作改为沉淀经验或进入 offer 决策。

邮件提醒状态按这些规则维护：

- 新增可投岗位: `邮件提醒状态=待发送`，`邮件提醒原因=新增可投`。
- 截止日期 3 天内且状态为待用户确认/未投: `邮件提醒状态=待发送`，`邮件提醒原因=截止临近`。
- 邮件发送成功: `邮件提醒状态=已发送`，写入 `上次邮件时间`。
- 邮件工具不可用或发送失败: `邮件提醒状态=发送失败`，在复盘记录里说明原因。
- offer/拒绝/放弃: `邮件提醒状态=无需发送`。

## 默认筛选视图

生成表格后建议用户按这些视图管理：

- `今日处理`: 提醒级别为今日处理。
- `本周投递`: 状态为待用户确认/未投，且提醒级别不是无需提醒。
- `高匹配主攻`: 匹配等级为高匹配主攻，按截止日期升序。
- `流程中`: 状态为已投/笔试/面试。
- `结果复盘`: 状态为 offer/拒绝/放弃。

## 在线文档创建规范

只有用户确认 Markdown 预览后，才创建或更新在线文档。Markdown 预览用于确认银行清单和排序；Notion 工作台创建以 `references/notion-workspace-schema.md` 为准。

当 Notion 插件可用且用户确认时，创建一个数据库，标题建议为 `2027 届银行秋招投递工作台｜{目标城市}`。Notion 主表使用克制字段，避免把 Markdown 全量执行字段原样搬进去。

创建时按 `notion-workspace-schema.md` 完成:

- 固定字段: 银行名称、总行/分行、推荐岗位方向、银行类型、同类梯队、投递优先级、投递批次、开始时间、截止时间、投递日期、官方招聘网站、网申入口、公告链接、简历版本、投递状态、笔试、一面、二面、三面/终面、推荐理由、主要风险、下一动作、提醒日期、提醒状态、备注1、备注2。
- 固定视图: `Default view`、`P0主攻`、`本周处理`、`流程中`、`截止日历`、`提醒日历`、`结果复盘`。
- 固定后续入口: 创建成功后的 Notion URL 是后续维护、提醒、复盘和公告更新的主入口。

如果在线文档工具不可用，保留 Markdown 预览并提示用户连接工具；不要声称已创建在线文档。

## 周复盘输出

每次定期跟踪时，至少输出：

```markdown
| 指标 | 本周数量 | 变化 | 判断 |
|---|---:|---|---|
| 新增岗位 | ... | ... | ... |
| 已投递 | ... | ... | ... |
| 笔试/面试中 | ... | ... | ... |
| offer/拒绝/放弃 | ... | ... | ... |
| 今日处理项 | ... | ... | ... |
```

然后给出：

- 本周最该处理的 3-5 个岗位。
- 需要补材料的岗位族。
- 下周投递和复盘节奏。
- 所有仍需核验的截止日期、链接和官方标题。
